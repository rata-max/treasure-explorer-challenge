PROJECT-WIDE CONTRACT

Treasure Explorer Rulebook

These rules apply to every stage unless a stage page explicitly introduces a stricter rule.

ONE STAGE · ONE GENERIC AGENT · MANY MAPS
THE NON-NEGOTIABLE RULE

No exit, no score.

Collected treasure counts only when the agent reaches the exit. A safe baseline is valid; stronger planning earns a higher score.

00 / RUNNING A STAGE

One file, many independent runs.

Folder and single-map command

  • Extract the stage ZIP and open the folder containing agent.py, maps/, and treasure_explorer/.
  • Run python -m treasure_explorer --map maps/<map-file>.json --agent agent.py --view.
  • Change only the value following --map to test another map.
  • --view animates the run; --delay 0.4 slows it; --no-clear keeps every frame.

Run every released map

  • PowerShell: Get-ChildItem maps/*.json | ForEach-Object { python -m treasure_explorer --map $_.FullName --agent agent.py }
  • Bash/macOS: for map in maps/*.json; do python -m treasure_explorer --map "$map" --agent agent.py; done
  • Tests: python -m unittest discover -s tests -v
  • Each command starts a fresh run; the same unchanged agent.py is loaded for every map.

01 / OBJECTIVE AND EXECUTION

Observe. Plan. Act. Repeat.

Core objective

  • Reach the exit within the energy budget.
  • Collect valuable treasure without sacrificing a safe exit.
  • Reduce wasted movement and invalid actions.
  • Generalize across every map in the stage.

Turn structure

  • The engine calls choose_action(observation) once per turn.
  • The agent returns exactly one supported action.
  • The engine updates position, energy, collection state, and visible information.
  • The next decision uses the updated observation.

02 / ACTIONS AND ENERGY

Every decision has a cost.

Supported actions

  • MOVE_UP, MOVE_DOWN, MOVE_LEFT, MOVE_RIGHT
  • COLLECT while standing on an uncollected treasure
  • Cost is charged when entering a cell: normal, start, exit, and treasure 1; mud 4; water 7.
  • COLLECT costs 1. Week 1 maps contain only unit-cost terrain.

Invalid actions

  • Moving outside the map, into a wall, or without enough energy
  • Collecting without an available treasure at the current position
  • Returning an unsupported value or raising an exception
  • An invalid action leaves position and energy unchanged, consumes one turn, and subtracts 5 points after a successful exit.
  • Repeated invalid actions can also reach the map's maximum-turn limit.

03 / TREASURE, EXIT, AND SCORE

Optimize the complete expedition.

Treasure and exit

  • Arriving at a treasure does not collect it; use COLLECT.
  • Entering the exit immediately ends the run.
  • The exit is a final destination, not an intermediate waypoint.
  • Preserve the energy required for a safe exit.

Base score

  • Exit Bonus + Treasure Value + Remaining Energy - Invalid Penalties
  • Default exit bonus: 50.
  • Default invalid-action penalty: 5 per action.
  • A run that does not reach the exit receives 0.

04 / INFORMATION CONTRACT

Use only what the agent is allowed to know.

Observation

  • Observation may include turn, position, energy, visible grid, exit, and treasure information.
  • ? means unobserved, not safe or normal terrain.
  • Information may be remembered within the same run.
  • Separate runs must start with independent state.

Prohibited access

  • No access to original maps, hidden maps, seeds, or engine internals
  • No file discovery, networking, subprocesses, or environment probing
  • No reflection or side channels intended to recover hidden state
  • No information sharing between evaluation runs

05 / GENERALIZATION AND SUBMISSION

Submit an algorithm, not a route.

One generic agent

  • Submit the root-level agent.py included in each released stage ZIP.
  • The evaluator loads that same file independently for every map in the stage.
  • Do not branch on filenames, titles, seeds, dimensions used as fingerprints, or memorized layouts.
  • Using observed grid dimensions and contents as ordinary algorithm inputs is allowed.

Submission boundary

  • Modify and submit agent.py only unless a stage page explicitly requests a report.
  • Do not modify the engine, maps, runner, tests, or configuration; evaluation uses clean official copies.
  • Use Python 3.11+ and the standard library only unless a stage explicitly states otherwise.
  • Week 2 and Week 3 artifacts, exact filenames, and stage-specific limits are announced when those stages unlock.

06 / RUNTIME AND EVALUATION

Strong, safe, and efficient.

Runtime contract

  • The public Week 1 runner has a maximum of 500 turns and no separate per-action timer.
  • Infinite loops or an uncaught exception can terminate or invalidate a run.
  • Any later per-action, total-runtime, or memory limit must be stated on that stage page before release.
  • Viewer delay is display time and is not part of algorithm performance.

Evaluation signals

  • Per-map score: 50 + collected treasure + remaining energy - 5 × invalid actions, only after reaching the exit
  • Exit rate and invalid-action count across the stage map set
  • Runtime, code quality, and required design explanation
  • Week 3 Thursday may add unseen hidden-seed maps under its published evaluation contract.

07 / ACADEMIC INTEGRITY

Your agent must be your work.

  • Do not copy, distribute, or publish another student's solution.
  • Do not publish a complete solution before grading ends.
  • Do not extract, share, or identify hidden maps and seeds.
  • Declare external references, reused code, and permitted AI assistance.
  • You must be able to explain every important design decision.
