PROJECT-WIDE CONTRACT

Treasure Explorer Rulebook

These rules apply to every stage unless a stage page explicitly introduces a stricter rule.

ONE STAGE · ONE GENERIC AGENT · MANY MAPS
THE NON-NEGOTIABLE RULE

No exit, no score.

Collected treasure counts only when the agent reaches the exit. A safe baseline is valid; stronger planning earns a higher score.

01 / OBJECTIVE AND EXECUTION

Observe. Plan. Act. Repeat.

Core objective

  • Reach the exit within the energy budget.
  • Collect valuable treasure without sacrificing a safe exit.
  • Reduce wasted movement and invalid actions.
  • Generalize across every map in the stage.

Turn structure

  • The engine calls choose_action(observation) once per turn.
  • The agent returns exactly one supported action.
  • The engine updates position, energy, collection state, and visible information.
  • The next decision uses the updated observation.

02 / ACTIONS AND ENERGY

Every decision has a cost.

Supported actions

  • MOVE_UP, MOVE_DOWN, MOVE_LEFT, MOVE_RIGHT
  • COLLECT on an uncollected treasure
  • Normal, start, exit, and treasure terrain cost 1 on entry.
  • Mud costs 4; water costs 7; collecting costs 1.

Invalid actions

  • Moving outside the map or into a wall
  • Moving without enough energy
  • Collecting where no available treasure exists
  • Returning an unsupported value or raising an exception
  • Each invalid action incurs the published penalty.

03 / TREASURE, EXIT, AND SCORE

Optimize the complete expedition.

Treasure and exit

  • Arriving at a treasure does not collect it; use COLLECT.
  • Entering the exit immediately ends the run.
  • The exit is a final destination, not an intermediate waypoint.
  • Preserve the energy required for a safe exit.

Base score

  • Exit Bonus + Treasure Value + Remaining Energy - Invalid Penalties
  • Default exit bonus: 50.
  • Default invalid-action penalty: 5 per action.
  • A run that does not reach the exit receives 0.

04 / INFORMATION CONTRACT

Use only what the agent is allowed to know.

Observation

  • Observation may include turn, position, energy, visible grid, exit, and treasure information.
  • ? means unobserved, not safe or normal terrain.
  • Information may be remembered within the same run.
  • Separate runs must start with independent state.

Prohibited access

  • No access to original maps, hidden maps, seeds, or engine internals
  • No file discovery, networking, subprocesses, or environment probing
  • No reflection or side channels intended to recover hidden state
  • No information sharing between evaluation runs

05 / GENERALIZATION AND SUBMISSION

Submit an algorithm, not a route.

One generic agent

  • Submit one agent.py for each released stage.
  • The same file runs on every public and evaluation map in that stage.
  • Do not branch on map names, seeds, or known layouts.
  • Do not store precomputed answer paths.

Submission boundary

  • Modify and submit agent.py only.
  • Do not modify the engine, maps, runner, tests, or configuration.
  • Evaluation uses a clean official engine.
  • Use Python 3.11+ and the standard library unless stated otherwise.

06 / RUNTIME AND EVALUATION

Strong, safe, and efficient.

Runtime contract

  • Return every action within the published time limit.
  • Infinite loops and unbounded search are failures.
  • Memory, total runtime, and maximum turns may be limited.
  • An uncaught exception may terminate the run.

Evaluation signals

  • Normalized score across multiple maps
  • Exit rate and invalid-action count
  • Average and worst-case robustness
  • Runtime, code quality, and design explanation
  • Week 3 includes unseen hidden-seed maps.

07 / ACADEMIC INTEGRITY

Your agent must be your work.

  • Do not copy, distribute, or publish another student's solution.
  • Do not publish a complete solution before grading ends.
  • Do not extract, share, or identify hidden maps and seeds.
  • Declare external references, reused code, and permitted AI assistance.
  • You must be able to explain every important design decision.
